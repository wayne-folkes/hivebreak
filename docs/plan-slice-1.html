Plan · slice 1 of Hivebreak · approved 29 Oct 2026

Hivebreak

One full run you can play on a phone held upright or on a desktop: five waves of aliens, an upgrade pick after each, combo scoring and a local high score. It works with keyboard, touch and a controller.

The pictures below are concept renders, drawn live on this page with Three.js. They use the same pipeline as the game: low-poly 3D models, stepped toon lighting, a dark outline, all rendered at the game's 180 × 320 art resolution and scaled up by whole pixels. The shapes are stand-ins; the real models come from Blender scripts in step 4.

Concepts

The cast

One ship and three alien types for slice 1. Each is built from separate parts so wings, eyes and cores can move in code.

Breaker

Your ship. Moves left and right, fires up; upgrades change how.

Drone

The bulk of the formation. One hit, fires now and then.

Warden

Armoured, takes two hits, fires shots aimed at you.

Diver

Breaks formation to swoop at you, then returns.

On desktop

Done means

  • A full run plays from the title to a win after wave 5, or to game over, and back to the title.
  • Keyboard, gamepad (Xbox and PlayStation layouts) and touch on a portrait phone all work, and you can switch mid-run.
  • Ship and aliens are Blender-scripted models rendered in the pixel style.
  • npm test, typecheck and build pass, CI is green, and it's live at hivebreak.folkes.dev.

Steps

In order. Once step 1 has fixed the shared types, steps 2, 3 and 4 don't depend on each other and can run in parallel. Routine coding goes to the implementer subagent; design and review stay in the main session.

  1. Sim core types

    main session

    The shapes everything else builds on: a seeded RNG so runs and tests are reproducible, and the player (kept in an array for co-op later), shots, aliens, waves, upgrades, the run, and the events sound and effects react to.

    game/rng.ts · game/types.ts

  2. Simulation

    paralleltested
    • Ship movement, fire rate, a moment of safety after a hit.
    • Formation march, step down, speed-up as it thins, enemy fire.
    • Drone, Warden and Diver behaviour; collisions with simple boxes.
    • Five waves as data; the upgrade pool and the three-card offer.
    • Combo scoring up to x8, reset on a miss; local high scores.
    • A full run played by a scripted bot as a test, the way rc-racer tests whole races.
    player · formation · aliens · collision · waves · upgrades · scoring · run · records

  3. Input

    parallel
    • Port controls, keyboard and gamepad from rc-racer, with ship input instead of car input.
    • New touch module: relative drag in the lower screen, auto-fire while held, a pause button.
    • Controller rumble when you're hit.
    controls.ts · input.ts · gamepad.ts · touch.ts

  4. Models

    parallelneeds your OK
    • Install Blender with brew install --cask blender.
    • Shared helpers: materials by role (hull, accent, glow), named moving parts, .glb export.
    • One script each for the ship, Drone, Warden, Diver and shots; npm run models rebuilds them all. The .glb files are committed, so CI and Vercel never need Blender.
    art/blender/*.py → client/public/models/*.glb

  5. Renderer

    • 180 × 320 render at whole-pixel scale, tilted orthographic camera (already scaffolded).
    • Toon lighting, 1-pixel outline, palette pass.
    • Load the models, animate parts, hit-flash; starfield, pixel explosions, screen shake.

  6. UI and sound

    • Title, how to play, settings, pause, the upgrade pick, game over and win with high score, in rc-racer's menu style.
    • HUD with score, combo, lives and wave.
    • Sound effects made in code for shots, hits, kills, upgrade picks, wave clears and game over.

  7. Ship it

    needs your OK
    • README with controls and how to run.
    • Create the public repo wayne-folkes/hivebreak, the Vercel project and the hivebreak.folkes.dev domain; follow CI and the deploy through.
    • Play-test on a phone and with a controller; tune speeds, fire rates and upgrade values.
